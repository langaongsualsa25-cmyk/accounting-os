## ข้อห้ามที่ทีมพัฒนาต้องถือเป็นเงื่อนไขบังคับ

- ห้ามให้ผู้ใช้พิมพ์ข้อมูลนิติบุคคลสำคัญซ้ำในหลายโมดูล หากมี Company Master ที่อนุมัติแล้ว

- ห้ามแก้ข้อมูลสำคัญทับของเดิมโดยไม่สร้างเวอร์ชันและ Audit Log

- ห้ามให้ผู้แก้ข้อมูลเป็นผู้อนุมัติการแก้ไขรายการเดียวกัน

- ห้ามนับผู้พบข้อผิดพลาดหรือผู้ถือครองงานปลายทางเป็นผู้ทำผิดโดยอัตโนมัติ

- ห้าม AI อนุมัติเอกสารราชการ ออกใบเตือน หรือหักคะแนนพนักงานเอง

- ห้ามส่งข้อมูล เอกสาร หรือคำถามของผู้ใช้ไปยัง External AI/API

- ห้ามใช้ Active–Active/Master-to-Master แบบไม่มีระบบจัดการ Conflict
  สำหรับข้อมูลบัญชีและนิติบุคคล

# ส่วนที่ 4 — Company Registration Wizard และ Company Master

## 4.1 ข้อมูลก่อนจดบริษัท (Registration Case)

- ชื่อบริษัทไทย/อังกฤษและชื่อสำรอง 3 ลำดับ

- ทุนจดทะเบียน จำนวนหุ้น มูลค่าต่อหุ้น และอัตราชำระ

- บุคคลหนึ่งรายเก็บครั้งเดียว แล้วผูกบทบาทผู้ถือหุ้น/กรรมการ/ผู้มีอำนาจลงนาม/ผู้รับมอบอำนาจ

- จำนวนหุ้น หมายเลขหุ้น สัดส่วน และมูลค่าของผู้ถือหุ้นแต่ละราย

- ที่ตั้งสำนักงานใหญ่ เลขรหัสประจำบ้าน และเอกสารสิทธิ/หนังสือยินยอม

- วัตถุประสงค์ ประเภทธุรกิจ ตราประทับ/โลโก้

- เอกสารตัวบุคคล Laser ID/Passport และวันหมดอายุ

- หลักฐานการชำระทุนและเส้นทางเงิน

## 4.2 กฎตรวจสอบอัตโนมัติ

| **กฎ**     | **เงื่อนไขผ่าน**                                               |
|------------|-------------------------------------------------------------|
| โครงสร้างทุน | ทุน ÷ มูลค่าหุ้น = จำนวนหุ้นทั้งหมด และเป็นจำนวนเต็ม                   |
| หุ้น         | จำนวนหุ้นรวมตรงกับหุ้นทั้งหมด สัดส่วนรวม 100% หมายเลขหุ้นไม่ซ้ำและต่อเนื่อง |
| บทบาท      | กรรมการไม่จำเป็นต้องเป็นผู้ถือหุ้น และผู้ถือหุ้นไม่จำเป็นต้องเป็นกรรมการ      |
| อำนาจลงนาม | ระบุจำนวนผู้ลงนาม เงื่อนไขร่วม/เดี่ยว และการใช้ตราประทับครบ           |
| ตัวบุคคล     | ข้อมูลระบุตัวตนครบ เอกสารอ่านได้ และไม่หมดอายุ                      |
| ที่อยู่        | องค์ประกอบที่อยู่และหลักฐานสถานที่ครบตามประเภทการใช้                 |
| ความพร้อม   | ทุกหมวดผ่านและผู้ตรวจอนุมัติ จึงเปลี่ยนเป็น “พร้อมสร้างร่าง/พร้อมยื่น”       |

## 4.3 หลังจดทะเบียนสำเร็จ

เปลี่ยนข้อมูลที่อนุมัติจาก Registration Case เป็น Company Master โดยอัตโนมัติ
แล้วเพิ่มเลขทะเบียน วันที่จด หนังสือรับรอง บอจ.5 หนังสือบริคณห์สนธิ ข้อบังคับ
ทะเบียนกรรมการ/ผู้ถือหุ้น ภ.พ.20 ประกันสังคม ใบอนุญาต และข้อมูลธนาคารตามลำดับ

## Dependency ที่ต้องรองรับ

- Finish-to-Start: งานก่อนต้องเสร็จจึงเริ่มงานถัดไป

- Parallel: ทำหลายขั้นตอนพร้อมกันได้

- Start-Allowed/Close-Blocked: เริ่มได้แต่ปิดไม่ได้จนเงื่อนไขก่อนหน้าครบ

- Override by Approval: ข้ามได้เมื่อผู้มีอำนาจอนุมัติและระบุเหตุผล

# ส่วนที่ 6 — การควบคุมเอกสารและ Pre-submission Gate

| **ชั้นควบคุม**          | **ข้อกำหนด**                                            |
|----------------------|--------------------------------------------------------|
| Source Evidence      | ข้อมูลสำคัญทุกช่องต้องชี้กลับไปยังเอกสาร/แหล่งข้อมูลที่รองรับ          |
| Draft Isolation      | ข้อมูลและเอกสารฉบับร่างต้องติดป้าย “ห้ามใช้” และไม่แทนฉบับอนุมัติ    |
| Version Control      | เก็บค่าก่อน/หลัง ผู้แก้ เหตุผล วันเวลา และเวอร์ชัน                |
| Four-Eyes Review     | ผู้สร้างหรือผู้แก้ไม่ใช่ผู้อนุมัติรายการเดียวกัน                       |
| Pre-submission Check | ตรวจความครบถ้วน ความสอดคล้อง แบบฟอร์มรุ่น และวันมีผลก่อนพิมพ์/ยื่น |
| Immutable Audit      | ประวัติการกระทำสำคัญแก้หรือลบย้อนหลังไม่ได้                     |

# ส่วนที่ 7 — การแจ้งเตือนและการส่งต่อความรับผิดชอบ

1.  ระบบแจ้งผู้รับผิดชอบก่อนครบกำหนดตาม SLA และระดับความเสี่ยง

2.  ผู้รับผิดชอบดำเนินการ หรือเลือกสาเหตุที่ยังทำไม่ได้พร้อมหลักฐาน

3.  หากไม่ตอบสนองหรือมีความเสี่ยง ระบบส่งต่อหัวหน้าทีม

4.  หากเสี่ยงค่าปรับ ลูกค้า หรือกำหนดกฎหมาย ระบบแจ้งผู้บริหารทันที

5.  เมื่อส่งต่อถูกต้อง ระบบเปลี่ยน Current Accountability Owner และเก็บเวลารับทราบ

6.  ใช้ In-app Notification, WebSocket, Private Mail หรือ Private PWA;
    ไม่ใส่ข้อมูลลับใน LINE

## ตัวชี้วัดที่ต้องคำนวณ

**อัตราความผิดพลาดของขั้นตอน =** (จำนวนงานผิดในขั้นตอน ÷
จำนวนงานทั้งหมดที่ผ่านขั้นตอน) × 100

**สัดส่วนข้อผิดพลาดทั้งหมด =** (จำนวนข้อผิดพลาดจากขั้นตอน ÷ ข้อผิดพลาดทั้งหมด) × 100

**หลักความเป็นธรรม:** รายงานทั้งจำนวนครั้งและอัตราต่อปริมาณงาน แยก “ผู้พบ”
“ผู้ถือครองงาน” “ผู้ส่งต่อ” และ “ต้นเหตุที่มนุษย์ยืนยันแล้ว” ออกจากกัน

## Acceptance Criteria สำคัญ

- บริษัท A ไม่สามารถมองเห็นข้อมูลหรือชื่อไฟล์ของบริษัท B ได้ทุกช่องทาง รวม Search,
  Notification และ AI

- ผู้ใช้ไม่สามารถนำข้อมูล/เอกสาร Draft ที่ยังไม่อนุมัติไปสร้างฉบับพร้อมยื่น

- ทุกการแก้ Company Master แสดงค่าเดิม ค่าใหม่ ผู้แก้ เหตุผล ผู้อนุมัติ และเวลาครบ

- เมื่อพบข้อผิดพลาด สามารถย้อน Timeline ถึงผู้สร้าง/แก้/ตรวจ/อนุมัติ/ส่งต่อและเวอร์ชันที่ใช้

- กำหนดเวลาคำนวณตามกฎและวันหยุด โดยเปลี่ยนกฎได้โดยไม่แก้โค้ดหลัก

- AI ไม่ตอบข้อมูลที่ผู้ใช้ไม่มีสิทธิ์ และทุกข้อสรุปสำคัญชี้กลับไปยังหลักฐานได้

- Backup สามารถ Restore ในสภาพแวดล้อมทดสอบได้จริง ไม่ใช่เพียงมีไฟล์สำรอง

- ระบบยังคงบันทึก Audit และแสดงสถานะสอดคล้องเมื่อเกิด retry, duplicate request
  หรือ network interruption
